# 后续计划 — 对标 RAGFlow + 解析能力服务化

> 战略路线图（2026-08 定稿，暂不执行，先放着）。
> 背景结论：本项目核心问答链路与 RAGFlow 差距约 70-80%（单用户体验），真正差距在**平台层**（多租户/多格式/UI/Agent/规模化）而非检索质量。本项目的独特价值是**中文教育/企业文档深度解析**（考试题切片、MathType 公式、图表描述），RAGFlow 默认覆盖不到。
>
> 两个方向**兼顾**：A. 补平台差距；B. 把解析能力打磨成可复用独立服务。

---

## 方向 A — 平台化：补齐与 RAGFlow 的差距

### A1. 多格式解析（最高优先级）
**现状**：仅 PDF/Word。RAGFlow 支持 260+ 格式。
- [ ] Excel（openpyxl）→ 表格感知切片
- [ ] PPT（python-pptx）→ 每页文本 + 图注
- [ ] Markdown / HTML → 直接结构化
- [ ] 扫描件批量 → Qwen-VL 页识别（已有能力，补批量）
- **交付**：`/documents/upload` 接受新格式；`tests/integration/` 各格式冒烟
- **验证**：上传 Excel/PPT，检索命中对应内容

### A2. 知识库管理（高优先级）
**现状**：单 collection `documents_v2`，无目录/文件管理。
- [ ] 多知识库（Qdrant 多 collection，`kb_id` 隔离）
- [ ] 文件管理（列表/删除/重传，已有部分）
- [ ] 文档级权限隔离（`source_files` 过滤已有，补 kb 级）
- **交付**：`/api/v1/knowledge-bases` CRUD；`/query` 支持 `kb_id`
- **验证**：建两个 KB，分别索引，查询互不串扰

### A3. 多用户 / RBAC
**现状**：单 Bearer token。
- [ ] 用户表 + 登录（JWT）
- [ ] 角色（admin/editor/viewer）
- [ ] API Key 管理（按用户）
- **交付**：`/api/v1/auth/*`；中间件鉴权
- **验证**：不同角色权限差异生效

### A4. Web 界面增强
**现状**：极简管理页（上传/问答/审核）。
- [ ] 知识库管理页
- [ ] 文档树 + 切片预览
- [ ] 对话历史 + 引用高亮
- **交付**：静态页扩展（`src/api/static/`）
- **验证**：完整操作流走通

### A5. Agent 工作流（低优先级，量大）
- [ ] 多跳检索（先检索→再查证→再回答）
- [ ] 可视化编排（超纲，仅做简单 DSL）
- **交付**：`/api/v1/agent/*`
- **验证**：多跳问题答案正确率对比

### A6. 规模化部署（低优先级）
- [ ] Qdrant 独立服务（从本地文件→server）
- [ ] docker-compose 拆分（app/redis/qdrant/mysql）
- [ ] 横向扩展（Celery worker 已有雏形）
- **交付**：生产 docker-compose
- **验证**：多实例负载下无锁冲突

## 方向 B — 解析能力服务化

### B1. 解析内核稳定化（高优先级）
**现状**：`/documents/parse` 纯解析端点已存在，但输出 schema 未固定。
- [ ] 固化解析输出 schema（pages/blocks/chunks/公式/表格/图表 JSON）
- [ ] 解析版本化（`schema_version`）
- [ ] 错误码体系（版面失败/OCR 失败/识别超时分级）
- **交付**：`src/parser/` 作为独立可导入包，无 FastAPI 依赖
- **验证**：纯 `python -c` 可调用解析内核，不依赖 app

### B2. 深度解析能力打磨（高优先级）
- [ ] 考试题切片再强化（选项合并、题号识别健壮性）
- [ ] 公式识别置信度分级（pix2tex 失败→Qwen-VL→标记待审）
- [ ] 图表描述可配置（模型选择/批大小/超时）
- **交付**：各能力可开关、可配置
- **验证**：用真实试题/论文回归，切片完整性 ≥ 95%

### B3. 插件化集成（中优先级）
- [ ] 输出对齐 RAGFlow 文档格式（供其作为前置解析器）
- [ ] CLI 单文件解析工具
- **交付**：`python -m src.parser file.pdf -o out.json`
- **验证**：同一文件 RAGFlow 与本项目解析结果可互导

## 阶段路线（建议执行序）

| 阶段 | 内容 | 预估 |
|------|------|------|
| ① 近期 | A1 多格式 + B1 内核稳定化 | 2-3 周 |
| ② 中期 | A2 知识库 + B2 能力打磨 | 2-3 周 |
| ③ 中期 | A4 UI + B3 插件化 | 2-3 周 |
| ④ 远期 | A3 RBAC + A5 Agent | 3-4 周 |
| ⑤ 远期 | A6 规模化 | 按需 |

## 优先级原则

1. **能增强现有核心价值的先做**：B1/B2（解析内核）是 A 的前提
2. **用户可感知的靠前**：A1（更多格式）> A2（知识库）> A4（UI）
3. **不重造平台**：RBAC/Agent/规模化若时间紧，优先做集成而非自研
