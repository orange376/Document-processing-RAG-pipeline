# 成熟技术路线改造方案

> 2026-08-11。目标：采纳 GitHub 上成熟的 RAG/文档解析技术，缩小与商业软件的性能差距。
> 原则：**采纳成熟基础设施，保留独有的中文公式/试题解析能力**（不整套替换）。

---

## 现状 vs 成熟方案（调研结论）

| 环节 | 我们 | 成熟方案 | 差距 |
|------|------|----------|------|
| 通用文档解析 | PP-DocLayoutV3 ~2s/页 | **Docling 0.76s/页**（MIT） | 2.6 倍 |
| 数学/公式解析 | pix2tex（强） | MinerU UniMERNet（顶尖但慢/AGPL） | 我们更强，保留 |
| 重排 | 重排全部 30 对 | **只重排 top-10**（cross-encoder 精度/双编码器速度） | 可砍 ~0.5s |
| 向量检索 | Qdrant 本地 | **Infinity 0.1ms** / Qdrant server | 高并发差距 |
| 重排模型 | bge-reranker-base | **bge-reranker-v2-m3**（成熟项目标配） | 质量差距 |

---

## 改造项

### ① 重排只取 top-10（立即实施）⭐
**现状**：`hybrid_search.search(top_k=30)` → reranker 对全部 30 对评分。
**改造**：rerank 前先按混合分粗筛 top-10，cross-encoder 只精排这 10 对 → 检索省 ~0.5s，质量无损（社区共识：top-10 重排足够）。
**影响**：retrieve ~2.4s → ~1.5s。

### ② Docling 通用解析（大改造，需评估）⭐
**现状**：自研 PP-DocLayoutV3 版面 + easyocr + 启发式降级。
**改造**：接入 IBM Docling（MIT）：
- DoclingDocument 结构化输出（标题/段落/表格/图片层级）
- TableFormer 复杂表格（优于我们）
- 原生 Office（Word/PPT/Excel）
- **保留**：pix2tex 公式路径 + Qwen-VL 图表 + 中文试题切片（Docling 丢公式图片，我们补）
**成本**：模型 ~7GB 下载（hf-mirror）；需回归中文/数学文档质量；license MIT 商用友好。
**风险**：中——Docling 中文/数学弱，需混合路由（Docling 通用 + 我们专用公式）。

### ③ Qdrant 本地 → server 模式（部署改造）⭐
**现状**：`qdrant_client.QdrantLocal` 本地文件，单进程锁。
**改造**：Qdrant server（docker 或二进制），多进程/高并发访问；dense-only 场景可换 **Infinity**（0.1ms、单二进制、内置混合+重排）。
**成本**：部署结构变化；数据迁移（已有 documents_v2 需重索引或 snapshot）。
**风险**：低-中。

### ④ bge-reranker-v2-m3（质量升级，⚠️ 与内存目标冲突）
**现状**：bge-reranker-base（107M）。
**改造**：v2-m3（600M），成熟项目标配，重排质量更高。
**⚠️ 冲突**：~600M 参数，加载后内存 +1~2GB——与"启动 4.28GB → 1GB"的内存优化目标**直接矛盾**。
**建议**：**暂缓**，除非换更大的机器（16GB+）。或在内存优化（方案 E）完成后，评估实测质量收益再定。

## 实施顺序

| 优先级 | 项 | 收益 | 风险 | 状态 |
|--------|-----|------|------|------|
| ① | 重排 top-10 | 检索 -0.5s | 低 | **立即做** |
| ② | Docling | 解析 2s→0.76s/页 | 中 | 评估可行性后做 |
| ③ | Qdrant server | 高并发 | 低-中 | 部署时做 |
| ④ | v2-m3 | 重排质量 | 高（内存）| **暂缓**，用户定夺 |

## 验证

- ①：查询计时日志对比 retrieve 耗时
- ②：同一批 PDF（含公式/图表/中文）Docling vs 现状，比较解析质量与耗时
- ③：多进程并发访问无锁冲突
